# LAB-0.10 — Sessão de rede do cache

## Estado inicial

HEAD `64102adf0bd78f032ec3c95a655d95f52baf5734`; árvore limpa. O LAB-0.9 havia
resolvido `uname.exe` ausente, mas o cache ainda não transferia até o fim.

## Evidência principal

Foram encontrados cURL 7.55.1/WinSSL do Windows e cURL 8.21.0/Schannel do Git.
`Git\usr\bin` não contém cURL; portanto sua precedência resolvia `uname` e
`chmod`, mas mantinha o cURL antigo. DNS e TCP 443 para o host real do cache
passaram; não havia proxy configurado. Ambos os cURLs completaram probes HTTP.

O cache continuava criando `C:\Windows\System32\curl.exe` mesmo com o Git
mingw no PATH. Foi usada a precedência interna documentada no código:
`%USERPROFILE%\.cache\mathlib\curl-7.88.1`, preenchida com uma cópia de hash
verificado do cURL Git 8.21.0. A captura de processo confirmou esse caminho e a
linha `--parallel --retry 5 --config ...\curl.cfg`.

## Download e parada

O download direcionado de `Mathlib.Tactic` recebeu 398 `.ltar`, deixou 2.583
`.part` e elevou `.olean` de 920 para 1.173. O config continha 2.981 URLs. Após
60 s sem novos bytes/arquivos, os processos do laboratório foram encerrados.
`Mathlib.Tactic.olean` não foi produzido; smoke mínimo PASS, tática e umbrella
FAIL por `.olean` ausente. Cache completo e build não foram iniciados.

## Estado final

Foi criado `10_TOOLS/lean-env.ps1` para descobrir/validar os binários, instalar
o cURL moderno no caminho interno esperado e executar Lean/Lake sem mudar o
PATH global. `LAB-BENCH-001` permanece bloqueado; `RH-NOGO-001` não foi aberto.
